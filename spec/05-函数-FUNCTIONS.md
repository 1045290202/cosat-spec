## 文法

形式文法见 [10-文法 §10.5、§10.2](./10-文法-GRAMMAR.md)。

定义不是独立文法：**定义 = lambda 链首 + `-> def 名字` 段**（[04-链模型 def 定义站点](./04-链模型-CHAIN.md)）。

## §6.1 定义（构造 + 流入 def）

体 = 表达式（单行）或块（多行）：

```cosat
\ x => x * 2;                          # 单行 lambda（表达式）
\ x => x * 2 -> def double;            # 定义：体 = x * 2（到 -> 止），函数流入 def
\ => 42;                               # 零参
```

```cosat
\ x => {                               # 多行块体
    x * 2 -> def m;
    m + 1                              # 块尾无分号 = 出口：块值 = m + 1（隐式返回）
} -> def doubleIncr;
```

### 双箭头分工（🔒 定案）

`->` 唯一含义 = 传递（管道），`=>` 唯一含义 = 函数定义（形参 → 体）；动机见 [design/05](../design/05-函数.md)。判定边界——两箭头出现在不同语法位置，词法与文法层均无歧义：

| 位置 | 用哪个 | 示例 |
| --- | --- | --- |
| `\` 后形参到体 | `=>` | `\ x => x * 2` |
| 链段数据到目的地 | `->` | `data -> @fn` |
| lambda 体内嵌套管道 | `->`（须块体或括号包裹） | `\ x => { x -> @fn }`、`@(\ x => x -> @f)`（`=>` 只在定义处出现一次） |

### 体边界规则（`->` 高于函数声明，🔒 定案）

一切位置统一：单行体自 `=>` 后开始扫描，遇到所在文法位的**第一个未配对封闭符**为止；配对块 / 括号内的同名符号不截断（扫描跳过配对单位）。语句位与站点位的封闭符都含 `->`，故**单行体内不能裸写管道**——要管道就换封闭环境（块体 / 括号）。动机见 [design/03](../design/03-运算符.md)、[design/09](../design/09-链上定义.md)。

| 体所在位置 | 终止符 | 示例 |
| --- | --- | --- |
| 语句位（链尾 def 前） | `->` 或 `;` | `\ x => x * 2 -> def double`：体 = `x * 2` |
| 裸链中站点位（`@\`） | `->` / `;` | `data1, data2 -> @\ a, b => b, a -> @fn`：体 = `b, a` |
| 分支体位 | `;`（语句位单行体分隔）/ `}` | `match x { _ > 0 : \ v => v + 1; _ : 0; }` |
| 循环体位 | `}` | `each xs { \ x => x * 2 }` |
| 括号内 | `)` | `data -> @(\ x => x -> @f)`：体内可含管道 |
| 参数组成员（链首组） | `,` 或 `->` ⏳ | `,` 与 `->` 的优先级待定（开放问题 7）；括号形无歧义可用 |

```cosat
\ x => x -> @double -> @inc;   # ✕ 体到第一个 -> 止：体 = x，语义变为「恒等函数流入 @double」
\ x => { x -> @double -> @inc }   # ✓ 管道入体必须块体
```

块体以配对 `}` 闭合，不受截断影响。

### 定义语义

- **递归**：函数定义可提升，体内可引用自身及互相调用；
- **返回值 = 体块值（隐式）**：块尾无分号语句的值流出（[08-语句](./08-语句-STATEMENTS.md)）；副作用出口写分号；无 return 概念，提前返回用 match 分支表达；
- **作用域**：`-> def` 绑定在所在作用域，可见性从绑定点起（[04-链模型](./04-链模型-CHAIN.md)、[design/09](../design/09-链上定义.md)）；无变异——同名 def 是遮蔽式新绑定；
- **分次传参** ⏳：用显式闭包——`\ b => { 1, b -> @add } -> def addB;`；自动部分应用待类型系统后解禁。

### 官方示例：斐波那契

综合展示构造/存储、match 值分发（泛化体）、括号嵌链、单表达式体。配套文法：`primary → "(" chain ")"`——括号分组内嵌链作为表达式；多语句体必须块（与 match 支路强制块同一理由），单表达式体可裸。

```cosat
\ n => match n {
    0 : 0
    1 : 1
    _ : (n - 1 -> @fib) + (n - 2 -> @fib)
} -> def fib;

10 -> @fib -> @print;                # → 55
```

## §6.2 调用

| 场景 | 写法 | 语义 |
| --- | --- | --- |
| 单参 | `data -> @f` | `f(data)` |
| 多参 | `a, b -> @f` | `f(a, b)` |
| 零参 | `@f` | `f()` |
| 链中合并多参 | `data -> _, x -> @g` | `g(data, x)` |
| 上游被 `@fn` 直接消耗 | `data -> @f1, x -> @g` | `g(f1(data), x)` |
| 动态站点 | `data -> (@@fn)` | ❓ 见 §6.4 注记 |
| 内联调用 | `data -> @(\ x => x * 2)` | lambda 就 data 立即应用 |
| 匿名函数传参 | `(\ x => x * 2), data -> @apply` | `apply(lambda, data)`；裸形切分待定（⏳ 开放问题 7） |

## §6.3 `@` 调用符（唯一调用标记）

裸标识符永远是引用（不调用），`@` 标记调用点：

| 写法 | 语义 |
| --- | --- |
| `fn` | 函数引用，不调用 |
| `@fn` | 调用 fn |
| `data -> @fn` | fn 接收 data 并调用 → `fn(data)` |
| `data -> fn` | **编译错**（站点位缺少调用标记） |

### 规则

- 文法：`@` callee，callee = 标识符 / dot 链 / 另一个 `@` 表达式（右结合）/ lambda 字面量（`@\ => body`）；
- 操作数限制：`@1`、`@"str"`、`@(a+b)`、`@!f` 均编译错；
- `@x`（变量持函数值）合法——高阶函数刚需；x 运行时非函数则抛运行时错误（类型系统前的既有代价）；
- 优先级：前缀，与单目同级，高于一切二元：`@f + 1` = `f() + 1`；
- **语义角色一致**：参数组内 `f` 传引用、`@f` 传调用结果。

### 多层 `@`：右结合，内层先执行，点位不跨层

`@@fn = @(@fn)`：内层先执行；点位始终来自 fn 本身的定义，`@` 层数只是叠加零参调用，编译器查 fn 定义即可：

| 写法（fn 为 1 参） | 展开（有左侧 data） | 展开（零参场景） |
| --- | --- | --- |
| `@fn` | `fn(data)` | `fn()` |
| `@@fn` | `fn(data)()` | `fn()()` |
| `@@@fn` | `fn(data)()()` | `fn()()()` |

### 立即调用家族（全部为既有原语的正交组合，零专用语法）

| 场景 | 写法 | 语义 |
| --- | --- | --- |
| 零参立即调用 | `@\ => 1;` | 立即执行，结果 = 1 |
| 零参块体立即调用（作用域隔离） | `@\ => { … };` | 立即执行，块内 `def` 不泄漏 |
| 数据流入 lambda | `data -> @(\ x => x * 2);` | lambda 就 data 立即应用 |
| 多参流入 lambda | `1, 2 -> @(\ x, y => x + y);` | 参数组 + 动态站点 |
| 裸 `@\` 带参重排形（链中） | `a, b -> @\ x, y => y, x -> @fn;` | 体到 `->` 止（§6.1 体边界），见 §6.5 |
| 命名函数取值 | `@f;` | `f()` |

## §6.4 站点位与接收点规则

站点位（`->` 右侧）= 接收者：必须自带显式接收点（公理 6），左侧参数数量与右侧点位总数匹配（[04-链模型 §5.1](./04-链模型-CHAIN.md)）。只允许：

| 形态 | 写法 | 接收点 | 语义 |
| --- | --- | --- | --- |
| `@` 标识符 / dot 链 | `-> @f`、`-> @obj.method` | f 的形参表 | 静态站点，显式调用 |
| `(` `@@` 表达式 `)` | `-> (@@fn)` | 返回函数的形参表 | 动态站点，显式括号表态 |
| `@(` lambda `)` | `-> @(\ x => x * 2)` | 内联形参 | 内联函数站点（立即调用） |
| `def 标识符` | `-> def d` | 名字（恰 1 位） | 定义站点：绑定并透传（tee） |
| `match _ { 分支 }` | `data -> match _ { … }` | 裸 `_`（arg 位） | match 段：上游 = 被匹配值 |
| `each _ { 接收者 }` | `data -> each _ { \ x => x * 2 }` | 裸 `_`（源位） | 循环站点：上游 = 源 |

**禁止**：站点位裸标识符（`data -> fn`）；站点位裸 `@`；站点位块（`-> {…}`）；泛化表达式站点（普通表达式 0 接收点，写入即断流编译错——带洞计算用 lambda：`data -> @(\ _ => _ + 1)`）。

站点位循环**必须以 `_` 为源**（`data -> each xs { }` 上游断流编译错），且源位仅限单独 `_`（`data -> each _, x -> @f` 编译错）；while 不可入链——详见 [07-循环 §7.3.4](./07-循环-LOOP.md)。类型系统落地后动态站点括号形态可进一步简化 ⏳。

> ❓ **动态站点语义待对齐**：`data -> (@@fn)` 存在 `fn()(data)` / `fn(data)()` 两解——按多层 `@` 右结合规则需定案其一。

## §6.5 多返回值与参数重排

### 多返回值

lambda 体为逗号表达式时返回参数组：

```cosat
\ a, b => b, a              # 接收 2 个值，返回 2 个值（交换顺序）
\ a, b, c => a, c           # 接收 3 个值，返回 2 个值（丢弃 b）
\ x => x, x * 2             # 接收 1 个值，返回 2 个值（复制 + 计算）
```

多返回值结果可直接流入下游：`@\ a, b => b, a -> @fn` → `fn(data2, data1)`。点位模型不变：作为**接收者**仍按**形参数量**暴露点位（[04-链模型 §5.1](./04-链模型-CHAIN.md)）；其结果流向下一跳时，按**返回值数量**与下游接收点位校验（编译期可分析逗号表达式）。

**命名限制**：def 恰好 1 位，多返回值只能解构命名、不可整体命名（整体命名待远期分组字面量 `(e1, e2)`）：

```cosat
@\ a, b => b, a -> def s1, def s2;    # ✓ 解构：s1、s2 各得 1 个
@\ a, b => b, a -> def s;             # ✕ 编译错：2 值 ≠ 1 点位
```

### 参数重排惯用模式（`@\`，不需要新符号）

```cosat
data1, data2 -> @\ a, b => b, a -> @fn               # 交换 → fn(data2, data1)
data1, data2, data3 -> @\ a, b, c => b, c, a -> @fn  # 旋转 → fn(data2, data3, data1)
data1, data2, data3 -> @\ a, b, _ => a, b -> @fn     # 丢弃 → fn(data1, data2)
data1 -> @\ a => a, a -> @fn                          # 复制 → fn(data1, data1)
data1, data2 -> @\ a, b => b, a + b -> @fn            # 重排 + 计算 → fn(data2, data1 + data2)
```

设计建议（超过 3 参应合并为对象而非复杂重排）见 [design/05](../design/05-函数.md)。

### 纯重排 β-内联优化

同时满足 **① 字面量**（非函数引用）、**② 纯引用**（体中每个表达式都是形参标识符的重排，无 `@fn`、无运算、无字面量）、**③ 单次应用** 时，编译器内联为参数重排，不生成函数调用：

```cosat
data1, data2 -> @\ a, b => b, a -> @fn          # ✓ 直接重排：零闭包零调用零临时变量
data1, data2, data3 -> @\ a, b, _ => a, b -> @fn   # ✓ 直接丢弃第三个参数
data1, data2 -> @\ a, b => b, a + 1 -> @fn      # ✕ 体中有计算 → 正常函数调用
data1, data2 -> @\ a, b => b, (a -> @process) -> @fn   # ✕ 体中有调用 → 正常函数调用
```

本优化是分支体字面 lambda β-内联（[06-匹配](./06-匹配-MATCH.md)）的特化；与其他归约方式的对比见 [design/05](../design/05-函数.md)。生成层流程：识别 `@\` 模式 → 检查体全为形参引用 → 形参引用替换为上游参数位置 → 直传下游。

## §6.6 开放问题

1. ❓ **参数组中裸标识符的点位**：`data -> @fn1, x -> @g` 中 `x` 暴露 0 位——方案 A：x 是已定义变量，取值入组；方案 B：非法。**倾向 A**；
2. ❓ **`@a.b` 的语义**：绑紧整个 dot 链（`(obj.method)()`，保持方法接收者）还是只调紧邻标识符（`obj().method`）。**倾向绑紧 dot 链**；
3. ❓ **lambda 字面量体是否需要 `@`**：match / 循环体位的 `\ x => …`——方案 A：体位自动立即调用；方案 B：也需要 `@`；方案 C：`\` 自带调用语义。**倾向 A**；
4. ❓ **零点位 fallback**：`data -> @@fn` 而 fn 为零参时右侧 0 位 ≠ 左侧 1 值——方案 A：编译错；方案 B：兜底投递。**倾向待定**；
5. ❓ **match / 循环体中函数引用的 `@`**：体中函数引用需要 `@`（全局一致），lambda 字面量在体位自动调用（同问题 3 方案 A）。**方向已定，待落文**；
6. ❓ **内置 / 外部函数 arity 声明**：点位校验依赖编译期已知形参数量，`@print` 等无 Cosat 定义可查——需要 arity 声明机制或末段放宽规则，待设计；
7. ⏳ **参数组内裸 lambda 的 `,` 切分**：`\ x => x * 2, data -> @apply` 存在两种自洽切分——实质是 `,` 与 `->` 的优先级问题，待定；定案前括号形无歧义可用。
