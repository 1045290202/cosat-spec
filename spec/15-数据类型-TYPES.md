## 文法

字面量的形式文法见 [12-文法 §12.1](./12-文法-GRAMMAR.md)；本章只写值域与语义约束。

## §15.1 值域总览

v0.1 的全部值分六类：

| 类型 | 字面量 / 构造形态 | 状态 |
| --- | --- | --- |
| number | `42`、`3.14`、`1_000`；负数经一元 `-` 构成 | 🔒 |
| string | `"hello"`（含转义，§15.3） | 🔒 |
| boolean | `true` / `false` | 🔒 |
| function | `\ x => x * 2`（构造式，[05-函数](./05-函数-FUNCTIONS.md)） | 🔒 |
| array | `[1, 2, 3]`——选型在途（[proposals/2026-08-23](../proposals/2026-08-23-数组结构选型.md)），章节号 13 预留 | ⏳ |
| object | `{ k: "v" }`——形态已定调（[proposals/2026-08-24](../proposals/2026-08-24-对象结构选型.md)），章节号 14 预留，挂起等待数组定案 | ⏳ |

三条明文立场（🔒）：

1. **无空值类型**：nil 不存在于值域。函数没有「无返回值」概念——块尾带分号是流控制语义（[08-语句](./08-语句-STATEMENTS.md)），不产生一种「空值」；nil 字面量维持废案立场（降级为可选补充，[10-废案](./10-废案-REJECTED.md)）。
2. **无类型标注**：类型不出现在源码中；静态标注归路线图远期（[11-路线图](./11-路线图-ROADMAP.md) 第 5 位）。
3. **无运行时类型查询机制**：类型是语义分类而非可观测接口——typeof 类内建、按类型分发均不存在；按类型匹配随模式匹配远期议（第 4 位）。

## §15.2 number

| 规则 | 内容 |
| --- | --- |
| 单一数值类型 🔒 | number = IEEE-754 双精度（binary64）；无 int / float 之分 |
| 整数精确范围 🔒 | 绝对值 ≤ 2^53 的整数值精确表示与精确运算；超出后按 IEEE 浮点舍入 |
| 算术语义 🔒 | 完全遵循 IEEE-754：溢出 → `±Infinity`；`0/0` → NaN；NaN 参与任何比较均为 false（含自身）；`-0 == 0` 为 true |
| 字面量格式 🔒 | 十进制整数与小数；`_` 分隔符允许出现于**两个数字之间**（`1_000`、`1_000.000_001`）；负数经一元 `-` 构成（§12.1 文法注记） |
| 未登记形态 ⏳ | 科学计数法、进制前缀归 [11-路线图](./11-路线图-ROADMAP.md)；当前写法编译错 |

分隔符细则（公理 5 审查，防 typo 静默漂移）：

```cosat
1_000          # ✓ = 1000
1_000.000_1    # ✓ 小数段同规则
1000_          # ✕ 编译错：分隔符必须夹在两数字之间
1__000         # ✕ 编译错：连续分隔符
_1000          # 标识符（标识符文法允许下划线开头），非数字
```

数字 token 必以数字开头，与裸 `_` 占位符、`_xxx` 标识符在首字符处分流，词法无两可状态。

## §15.3 string

| 规则 | 内容 |
| --- | --- |
| 字符模型 🔒 | string = Unicode 码点序列；遍历粒度 = 码点（each 可迭代字符串）|
| 字面量 🔒 | 双引号、单行；原始换行编译错（多行形态 ⏳ 归 [11-路线图](./11-路线图-ROADMAP.md)）|
| 转义集封闭 🔒 | 仅认五项：`\"` `\\` `\n`（U+000A）`\t`（U+0009）`\r`（U+000D）；**未知转义编译错**（`\q`、`\x` 等）——公理 5「弱者非法」，禁静默原样透传 |
| 插值 ⏳ | 模板插值不做，随多行字符串一并归远期 |

## §15.4 boolean

| 规则 | 内容 |
| --- | --- |
| 二值类型 🔒 | `true` / `false`，唯一布尔类型 |
| 严格布尔 🔒 | 条件语境只接受 boolean：when / while 守卫、单目 `!` 操作数；其它类型的值出现在条件位 = 运行时错误（v0.1 无类型系统，编译期不可查） |
| 无真值表 🔒 | 不存在隐式真假转换（`0`、`""` 等不参与条件判定）——与 §15.8 转换禁令同源 |

## §15.5 函数值

lambda 构造的函数是一等值：可作链值传递、`def` 绑定、复合结构成员（`[f, g]` 先例见数组提案）。函数之间比较按引用同一性（§15.7）。

## §15.6 复合结构登记（⏳）

- **数组**：选型进行中（[proposals/2026-08-23](../proposals/2026-08-23-数组结构选型.md)，spec/13 预留）。异构成员立场、「三位置体系」等以提案文档为准；本章仅预先约束其相等判定走引用同一性（§15.7）。
- **对象**：形态已定调（[proposals/2026-08-24](../proposals/2026-08-24-对象结构选型.md)，spec/14 预留），挂起等待数组可变性路径 A/B/C 定案。
- 两结构的成员读后缀（`.` 与 `[i]`）属 postfix 层基建，随各自轮次落地，不在本章范围。

## §15.7 相等语义（`==`）

`==` 是全语言唯一跨类型合法的二元运算（总函数）：任何两值可比且必有 boolean 结果，相等判定不存在运行时错误。

| 操作数组合 | 判定 |
| --- | --- |
| 类型不同 | false |
| number × number | 数值相等（IEEE 推论：`NaN == NaN` → false、`-0 == 0` → true） |
| string × string | 逐码点相等 |
| boolean × boolean | 同值 |
| function / array / object | 引用同一性——同一实例才 true |

推论与衔接：

```cosat
"a" + "b" == "ab"   # ✓ true：拼接结果按码点逐位比
\ => 1              # 与另一处独立书写的 \ => 1 是不同函数值：
                    # 两次构造的同内容复合值互不相等
```

- 内容级（深度）比较方案 ⏳ 归 [11-路线图](./11-路线图-ROADMAP.md)，届时另议；
- match 字面量分支的相等判定复用本节语义（分支左侧规则见 [06-匹配](./06-匹配-MATCH.md)：字面量 = 严格相等比较）。

## §15.8 运算符分派原则与隐式转换禁令

**顶层禁令（🔒）**：全语言禁止隐式转换——任何运算不把操作数转换为另一类型再参与运算。杜绝 JS 式静默吞错：混合类型恒为显式错误，且为未来类型系统引入保留零破坏性迁移路径。

**分派原则（🔒）**：二元运算符语义允许按操作数类型分派，但仅在**同型组合**上定义；混合类型组合一律运行时错误。唯一例外：`==` 按 §15.7 总函数。

当前登记表：

| 运算符 | number × number | string × string | 其它组合 |
| --- | --- | --- | --- |
| `+` | IEEE-754 加法 | 拼接（首个分派实例，2026-08-25 定案） | ✕ 运行时错误 |
| `-` `*` `/` | IEEE-754 算术 | 未登记 → ✕ 运行时错误 | ✕ 运行时错误 |
| `<` `>` | 数值比较 | 未登记（字典序 ⏳ 归远期） | ✕ 运行时错误 |
| 单目 `-` `+` | IEEE-754 | ✕ | ✕ |
| 单目 `!` | 仅 boolean 操作数（§15.4） | 同左 | 同左 |

```cosat
"a" + "b"        # ✓ "ab"；优先级随加法层（[03-运算符](./03-运算符-OPERATORS.md)）
"a" + 1          # ✕ 运行时错误：混合类型，无 toString 兜底
```

用户自定义重载协议（新类型 / 新符号注册）⏳ 随类型系统期议（[11-路线图](./11-路线图-ROADMAP.md)）：与第 7 位「前缀操作符协议」互补——那边管前缀新符号注册，这里管既有二元符号的类型实例扩展；新增中缀符号仍禁（判定封闭不变）。
