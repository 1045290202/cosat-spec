## 0. 背景

键值对复合数据目前在语言中没有字面量形态：

- 词法字面量只有 number / string / boolean；复合值仅 lambda 与 match/when/each/while 表达式（[12-文法](../spec/12-文法-GRAMMAR.md) §12.3）；
- 数组结构选型进行中（[proposals/2026-08-23](./2026-08-23-数组结构选型.md)），键值复合值是其后的下一个复合值缺口；
- v0.1 立场「无类型系统」（数组异构成员同款立场）：对象定位为**异构键值容器**，类型标注归路线图远期（[11-路线图](../spec/11-路线图-ROADMAP.md)，类型系统第 5 位）。

本轮范围已收敛为「核心+整合」：字面量形态 + 键写法 + 读路径（后缀/取站）+ 多行书写。
不在本轮：写入语义（挂数组可变性路径）、动态计算键、match 匹配/解构、类型声明。

形态已于 2026-08-24 讨论定调。本文档记录结论与否决理由，待随数组可变性路径一并落 spec。

## 1. 形态定案（讨论收敛 2026-08-24）

### 1.1 `{}` 按解析位置入住值位

对象字面量复用 `{}`——配对定界符家族学说（先例：数组提案 `[ ]` 三位置体系，「内部文法由解析位置决定」）。**零新符号**。

裸 `{` 全语言出场盘点：

| 解析位置 | 现状语义 | 判定 |
| --- | --- | --- |
| 构造关键词后（`each xs {` / `while {` / match 体） | 循环/分支块体 | token 前导，永不是对象 |
| `=>` 后 | lambda 块体（含空块体 `\ => {}`） | token 前导，永不是对象 |
| match 分支 `:` 后 | 分支接收者块（receiver = operand \| block 仅此语境） | token 前导，永不是对象 |
| `->` 之后 | ✕ 明文禁块：「站点位禁块」（[09-速查](../spec/09-速查-CHEATSHEET.md) 判定表、[05-函数](../spec/05-函数-FUNCTIONS.md) 站点形态禁止清单、[04-链模型](../spec/04-链模型-CHAIN.md)） | 无竞争 |
| **值位（链首 / 操作数位）** | 现状不可达 | **对象字面量入住** |

结论：全语言任何位置无两可状态（公理 5 文法层消灭歧义），无需新增守卫规则或扫描机制。

### 1.2 允许的用法

```cosat
{ name: "包裹", weight: 3 } -> @ship;   # 字面量占链值位（单值，点位 0）
{}                                     # 空对象（对仗空数组 []）
pkg -> def p;                          # tee 绑定，原值继续流
p.name -> @log;                        # 读后缀：`.` 成员访问
p -> ["快递单号"] -> @log;              # 取站读：字符串作索引，与数组取位站 xs -> [0] 同族
{ inner: { x: 1 }, tags: ["a", "b"] }  # 嵌套：成员为任意表达式
{ n: 1, "快递单号": "CST-001" }        # 标识符键为主；字符串键兼收任意名
{ name: "x", weight: 3, }              # 尾随逗号允许（与数组一致）
x, { k: 1 } -> @f;                     # 作参数组成员（普通操作数，点位 0）
each [{ n: 1 }, { n: 2 }] { \ o => o.n -> @log }   # 字面量作循环源；{} 本在配对跳过集内
```

### 1.3 不允许的用法

| 写法 | 判定 | 原因 |
| --- | --- | --- |
| `data -> { k: _ } -> @f;` | ✕ 编译错 | 站点位禁块维持原判；「流入即构造」不做，动态构造经函数中转（与数组打包原语 ❓ 同源，归库轮次） |
| `p."快递单号"` | ✕ 编译错 | `.` 只接标识符（dotted-name 先例）；任意名走 `["…"]` 后缀或取站 |
| `{ name }`（简写糖） | ✕ 本轮不做 | 需新增「裸标识符 = 从作用域取值」语境规则，与最小范围纪律不符 |
| `{ [k]: v }`（动态计算键） | ✕ 本轮不做 | 运行期构造难题归库轮次 |
| 换行免逗号（成员间不写 `,`） | ✕ 编译错 | 成员分隔强制 `,`；全语言 token 流扫描无「行」概念先例（match 分支体自定界不可平移到任意表达式成员），不为排版引入按行截断机制 |
| `v -> p.weight`（字段写入） | ⏳ 未定 | 写入语义挂数组可变性路径 A/B/C（见 §3.1）；若 B 胜出→对称形 `v -> p["weight"]` |

### 1.4 连带义务（易漏项，落地时执行）

- **文法**（选型参考，非定案文法）：

```ebnf
object-literal = "{" , [ member , { "," , member } , [ "," ] ] , "}" ;
member         = ( identifier | string ) , ":" , operand ;
(* primary 增补 object-literal（值位）；后缀访问层见下条 *)
```

- **postfix 读后缀层共建**：`p.name` 作普通操作数今天只在 callee 位存在（dotted-name），扩展到任意操作数位与数组索引后缀 `xs[0]` 是**同一 postfix 层级基建**（[03-运算符](../spec/03-运算符-OPERATORS.md) postfix 层级），两特性须协调落地顺序；
- **点位表**：[04-链模型](../spec/04-链模型-CHAIN.md) 点位计数表登记「对象字面量暴露 0 接收点位」一行；
- **速查表**：[09-速查](../spec/09-速查-CHEATSHEET.md) 增补对应 ✓/✕ 行；
- **双同步**：章节 EBNF 与 [12-文法](../spec/12-文法-GRAMMAR.md)；
- **无需动**：[02-符号](../spec/02-符号-SYMBOLS.md) 分工表（零新符号、零转正）、扫描配对跳过集（`{}` 本在集内）、[10-废案](../spec/10-废案-REJECTED.md)（无既有决定被推翻）。

## 2. 否决形态记录

### 方案甲：保留池符号前缀 `%{ name: "包裹" }`

- **利**：任何位置零歧义，公理 5 最强；Elixir map 同款先例。
- **弊（否决）**：`%` 在 [02-符号](../spec/02-符号-SYMBOLS.md) 明文「原则上不作前缀消费」（预留给模运算等二元运算）；启用须翻案登记并消耗稀缺符号池；另背前缀空格规则义务。为一个字面量烧掉一个二元运算位，代价失衡。

### 方案乙：关键词前缀 `obj { name: "包裹" }`

- **利**：关键词 token 边界自分隔，免空格规则；位置无关。
- **弊（否决）**：语言里关键词标记的是「构造」（match/when/each/while/def），字面量历来赤膊（`[1,2,3]` 无关键词帽）；给字面量戴关键词帽子风格不搭。

## 3. 派生待决项

### 3.1 写入语义（❗依赖数组选型）

[design/09](../design/09-链上定义.md) 无赋值语义约束数组与对象两边，分开定必然打架。待数组 A/B/C 定案后对称落：

- A（不可变+遮蔽重建）：对象更新走遮蔽式重建惯用形，操作归内置库轮次；
- B（名字不可变容器可变）：对称形态 `v -> p["weight"]`（槽位写入站）；`.weight` 不作接收者（裸名字围栏同理）；
- C（mut 双态）：跟随数组的 mut 标记结论。

### 3.2 动态构造与计算键

`{ [k]: v }` 计算键、「流入即构造」所需的打包能力，与数组打包原语（变参点位模型 ❓）同源，一并归内置库轮次议。

### 3.3 match 匹配对象 / 解构

跟随模式匹配远期挂账（[06-匹配](../spec/06-匹配-MATCH.md) §7.1.1 ⏳），形态届时统一设计，本轮不预埋语法。
