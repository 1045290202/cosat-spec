## 0. 背景

数组目前在规范中只有隐式存在：

- `each` 体尾无分号 → 收集为「数组」（≈ map），空源 → `[]`（[07-循环](../spec/07-循环-LOOP.md)）；
- 循环源运行时须可迭代（数组/字符串/Map/Set/生成器）；
- 路线图提到 deforestation 消中间数组。

字面量语法、索引访问、可变性立场均未设计。本轮讨论范围已定为「核心+整合」：字面量 + 索引读取 + 与链模型/each 的整合 + 可变性立场；内置函数库另议。

讨论中已收敛的共识见 §1；核心未决——可变性路径三案——见 §2。

## 1. 共同基建（三案通用，均已过冲突推演）

### 1.1 `[` `]` 二位置体系

`[` `]` 从未占用符号池转正为配对定界符家族成员（与 `{}` `()` 同族——内部文法由解析位置决定，先例：`.` 按上一 token 判定成员访问或小数点）：

| 解析位置 | 形态 | 语义 |
| --- | --- | --- |
| 表达式首位（primary） | `[1, 2, 3]` | 数组字面量 |
| 完整操作数之后 | `xs[0]`、`m[0][1]` | 索引后缀（读） |

两种出场一个语义家族（数组结构定位），无两可状态。读只走后缀；`->` 之后无站点形态（否决记录见 §1.5）。

### 1.2 允许的用法

```cosat
[1, 2, 3]                    # 字面量，成员从左到右求值
[]                           # 空数组（与 each 空源收集写法一致）
[x]                          # 单元素
[[1, 2], [3]]                # 嵌套，维度不限
[1, "a", true]               # 异构允许（v0.1 无类型系统）
[a + 1, b * 2]               # 成员为任意表达式
[f, g]                       # 成员为裸标识符 = 函数引用
[@f, @g]                     # 成员为零参调用，存结果
[1, 2, 3,]                   # 尾随逗号允许（2026-08-23 讨论定）
xs[0]                        # 后缀读
xs[i + 1]                    # 索引为任意表达式
m[0][1]                      # 后缀级联
[1, 2, 3][0]                 # 字面量立即索引
[1, 2, 3] -> @sum;           # 字面量占链值位（单值，点位 0）
each [1, 2, 3] { _ * 2 }     # 字面量作循环源（配对跳过集生效）
match xs[0] { … }            # 被匹配值含索引
x, [1, 2] -> @f;             # 数组作参数组成员（普通操作数，点位 0）
```

### 1.3 不允许的用法（通用部分）

| 写法 | 判定 | 原因 |
| --- | --- | --- |
| `xs[]` | ✕ 编译错 | 索引须恰一表达式 |
| `data -> [0] -> @f;` | ✕ 编译错 | 取位站不成立（§1.5）：读只走后缀 `xs[0] -> @f;`；链中匿名取位用内联形 `data -> @(\ x => x[0]) -> @f;` 或 `def` 中转 |
| `xs[-1]`、任何越界读 | 运行时错误 | v0.1 无 nil 兜底；负索引糖远期随内置库议 |

> 注意：「`xs[i]` 作站点」「不可变」两条判定**依赖可变性路径选择**，从通用清单中移出，分别见 §2 各案。

### 1.4 扫描规则连带义务（易漏项）

现有三条扫描规则「跳过配对括号与配对块」的配对集目前只有 `( )` `{ }`，必须加入 `[ ]`，否则合法写法误触禁集：

- `each [1, 2, 3] { … }` —— each 源扫描禁 `,`；
- `match m[i, j] { … }` 形态的被匹配值扫描同理。

同步面：10-文法 §10.1（`delimiter` 产生式补 `[` `]`、扫描级规则配对跳过集补 `[ ]`）、03-运算符（postfix 层级）、04-链模型（点位计数表加行：数组字面量暴露 0 点）、06/07（扫描规则文字同步）、02-符号（`[` `]` 出池登记）、10-文法（各章 EBNF 双同步）。

### 1.5 否决形态记录：取位站（管道式读）

第三位置 `xs -> [0] -> @f;`（`->` 之后的取位站点）曾列为三位置体系一员，2026-08-26 讨论否决：

- 表达力零增益：`m -> [0] -> [1] -> @f` 即 `m[0][1] -> @f`；链中匿名取位由内联形 `@(\ x => x[0])` 或 `def` 中转完全覆盖；
- 既有六种站点形态均为必要性所迫，取位站是首个「纯便利」站点，开站点闭集先例；
- 连带成本：「`->` 后首 token `[` 且 `]` 后紧跟 `->` / `;`」结构消歧规则、索引禁裸 `_` 特例（防双上游歧义）、`]` 后 `,` 的参数组形态，均需单独定案；
- 方案 B 世界里 `->` 两侧同挂读写两个 `[` 形态，否决后读只走后缀、写只走站点，分工更干净。

未来有真实使用证据重提时，按 [废案集](../rejected/README.md) 翻案登记流程办理。

## 2. 核心待决：可变性路径

现行相关定案：语言无赋值语义、`def` 是遮蔽式新绑定（[design/09](../design/09-链上定义.md)）；路线图挂有「远期显式容器」。以下三案均给出推导、形态、利弊。

### 方案 A：不可变本体 + 遮蔽式重建惯用形

**推导**：design/09 无变异定案的直接延伸——数组与其它值一样不可变；「修改」通过新数组遮蔽旧名实现，`def` 天然支持（`i + 1 -> def i` 已定案为新绑定遮蔽）。

**形态**：

```cosat
# 使用侧惯用形——写感是「原地追加」，语义是新数组遮蔽旧名：
xs, item -> @push -> def xs;      # @push 为纯函数（固定二元内置）：返回 新数组 = 旧 xs 全部元素 + item
```

**利**：

- 零机制新增：不动 design/09，不新增站点形态，本轮范围最小；
- 无别名心智负担：值语义处处成立，推理成本最低；
- 与函数式管线（链、each 收集、β-内联、循环融合）零摩擦，优化路径畅通；
- 先例充分：Clojure/Elixir/Immutable.js 同路数。

**弊**：

- 追加类操作全归远期内置库：纯 Cosat 无打包与参数组展开原语，push 类操作语言内不可表达（打包原语 §3.1 即使定案，仍缺展开机制）；
- 状态机、缓冲区、原地算法表达笨拙（每次「改」都是全量拷贝语义上、优化前也常是物理拷贝）；
- while 条件循环依旧缺状态机形态（路线图缺口继续挂着）；
- 「写感靠 def 遮蔽」对新手有语义落差（看着像改，实际是换）。

**连带问题**：本方案下 @push 为固定二元内置，无变参前置；打包与展开机制（§3.1）归库轮次，不阻塞本轮定案。

### 方案 B：名字不可变、容器可变（槽位写入站）

**推导**：接收点公理的正向推广。公理 6 要求接收者自带显式、裸露、唯一的接收点——容器的索引槽位恰好满足：一个坑、进一个值。于是读写形成完全对偶：

```cosat
xs[i] -> @f;   # 读：xs[i] 在操作数位，元素流出
v -> xs[i];    # 写：xs[i] 在站点位，值流入索引槽位
```

同一定位记法 `xs[i]`，按解析位置分读写——操作数位读、站点位写。

`->` 右侧新增第七种站点形态「槽位写入站」。同时修订 design/09 措辞并按纪律登记废案：

> 原：「语言无赋值语义」→ 修订为「**名字绑定无赋值；容器槽位写入走显式接收点**」。
> 一句话立场：**名字不可变，容器可变。**

**形态**：

```cosat
5 -> xs[0];                    # 替换第 0 位；产出 0 值，其后不得再接段（编译期可查）
v -> m[i][j];                  # 嵌套写：最内层槽位
xs -> def ys;                  # ys 与 xs 绑定同一数组（引用语义）
9 -> ys[0];                    # xs[0] 同步可见——别名明示为特性（Python 列表同款）
xs, item -> @push;             # 原地追加：@push 固定二元（数组+元素），变参难题不存在
while { @running : i + 1 -> slots[i]; }   # while 状态机形态解锁一半
```

**利**：

- 公理逐条过审且形态优雅：数据流 ✓ 目的地殿后 ✓ 符号单一含义（读写同一定位语义、按位置结构区分）✓ 文法消歧 ✓ 接收点显式 ✓✓（这是最贴合公理 6 的变异形态）；
- 读写对偶，认知负担低；
- 固定二元内置函数即可覆盖增删，**不触碰变参问题**；
- 半解锁路线图「显式容器」挂起的状态机需求；
- 「裸名字永远不能当接收者」的围栏保住了 design/09 的核心关切（变量无赋值语义）。

**弊**：

- 必须修订 design/09 并在 rejected/ 登记（纪律流程，非技术障碍但动历史定案）；
- 引用别名的心智负担进入语言（不可变世界没有此问题）；
- 本轮 ✕ 清单部分反转（原「`xs[i]` 作站点非法」在新世界正是写入形态），文档改动面最大：引用语义节、写入站规则、段判定第七行、最小内置集契约；
- v0.1 无类型系统，「对非数组槽位写入」只能运行时报错。

**围栏细则**（若选 B，一并定）：只有索引槽位能当接收者，裸名字不行（`v -> x` 仍非法）；写入站索引同样禁 `_`；越界写 = 运行时错误（替换不扩容，增减长度归内置）。

### 方案 C：mut 双态世界（默认不可变 + 显式标记才可变）

**推导**：试图兼得 A 的安全与 B 的能力——默认数组不可变，带显式标记（如 `mut` 关键词前缀）的数组才开放槽位写入与原地操作。即路线图「远期显式容器」的提前落地。

**形态**（示意）：

```cosat
mut [1, 2] -> def xs;          # 可变数组构造
5 -> xs[0];                    # ✓ 标记过的才允许
5 -> ys[0];                    # ✕ ys 不可变，编译错
```

**利**：

- 默认安全：可变性在构造点显式可见，读到 `mut` 才需担心别名；
- 函数式风格为主的世界里，突变被隔离在局部。

**弊**：

- 设计面最大：标记的传播性立刻成为必答题（`mut` 数组传给函数还是 `mut` 吗？合并段里混流怎么办？收集开关收出来的数组算不算 mut？）——这些本质是类型系统问题，无类型系统的 v0.1 只能用约定硬扛；
- 双套语义文档翻倍，每条数组规则都要写两遍（可变/不可变分支）；
- 新关键词 `mut` 占词表；或用符号前缀则加剧符号稀缺；
- Rust 先例表明该模型的收益高度依赖所有权/借用配套，单拎 mut 标记收益打折。

**先例检查**：路线图「远期显式容器」最接近本方案——选 C 相当于把远期工作提前到现在，与「遇 ❓ 先停下」的仓库节奏相悖。

### 对比总表

| 维度 | A 不可变+遮蔽重建 | B 名字不可变容器可变 | C mut 双态 |
| --- | --- | --- | --- |
| 动 design/09 | 否 | 是（修订+废案登记） | 是 |
| 新站点形态 | 无 | 槽位写入站 | 槽位写入站（限 mut） |

## 3. 派生待决项

### 3.1 打包原语与变参点位模型（❓ 独立开放问题）

缺口：v0.1 纯 Cosat 无法把运行期参数组打成数组——字面量成员是编译期写定的，而 `a, b -> ???` 没有任何接收者能产出数组。

难点：点位模型要求 `@fn` 形参数量固定（每跳校验：点位总数 = 上游参数数量），打包却是变参的。

候选方向（仅记录，不在本轮展开）：专用变参内置并在点位表中特例登记；或引入收集器站点形态。另注：打包即使定案，仍缺「参数组展开」（把数组元素拼入组）机制，push 类操作纯 Cosat 依旧不可表达。两问题三案均归内置库轮次，不阻塞本轮可变性定案。

### 3.2 内置最小集

- 方案 A：全部归远期内置库轮次（含 @push/@pack）；
- 方案 B/C：建议本轮只定 `@push` / `@pop` 最小契约（固定元数、原地语义、返回值约定），其余（insert/remove/splice/slice…）归库轮次。

### 3.3 若选 B/C：design/09 修订文案与废案登记稿

需起草：design/09 措辞修订、「名字不可变、容器可变」论证全文（进 design/10）、rejected/ 登记行（旧表述 + 修订理由 + 日期）。
