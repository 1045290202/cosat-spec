# 循环设计决策

对应 [spec/07-循环](../spec/07-循环-LOOP.md)。

## 关键词拆分动机（2026-08-22）

`~` 四形态中条件型与带源形态的结构差异最大（无源、守卫重评、不可入链、`_` 规则相反），拆出 `while` 后：源扫描规则只属 each，守卫每轮重评只属 while，各自成文、不再互相引用解释。each 保留三形态（遍历 / 带守卫 / 站点），三者共享「源 + 块」结构，无需再拆。词 token 先例与主流分工论证同 [design/06](./06-匹配.md)。

## `@done?` 更名 `@running`（2026-08-22）

原条件型示例谓词写法 `@done?` 有双重问题：

1. **非法**：[01-词法](../spec/01-词法-LEXICAL.md) 标识符文法不含 `?`，运算符表亦无后缀 `?`——该写法无法通过词法；
2. **极性误导**：条件循环臂在守卫为真时执行、全假退出——名为 `done` 的守卫为真时继续轮转，与直觉相反；更名 `running` 后极性自明（真 = 继续轮转，假 = 退出）。

否决「标识符允许尾缀 `?`」方案：公理 3 符号单一含义约束下 `?` 另担语义必生张力，且退役的 `?` 已保留给待定三元；改名成本最低。

## 收集开关 = 体尾分号的动机

- 用户定向"循环能有返回值"，但不想引入 return/collect 关键字；
- 语义分号（`;` = 值丢弃）延伸到迭代维度即可零新增规则：体尾无分号 → 收集为数组（≈ map），带分号 → 不收集（≈ forEach，零收集开销）；
- 编译期由 Block.tail 判定，副作用循环不生成任何收集代码。

**空值也入列**：体块值一律收集，静默跳过空值属被否决的隐式魔法——筛选语义应显式走守卫形态或库函数 filter，而非靠收集器猜。

## 源层 `_` 白名单的三条理由

源表达式顶层禁止 `_` 作子表达式成分（`_ * 2`、`_ * _`、`f, _` 均编译错；唯一合法 = 站点位单独 `_`）：

1. **单字符陷阱**：源位裸 `_` 与含 `_` 算式一字之差语义大变（`each _ { }` vs `each _ * 2 { }`）；
2. **需求全部有更清晰等价形态**：站点分解 `data -> @double -> each _ { 体 }`、match 选源 `data -> match _ { … } -> each _ { 体 }`、链上定义中转 `data -> def d; each d * 2 { 体 }`；
3. **从严到宽安全演进**：将来放开不破坏既有代码。

括号分组不改变 `_` 层级归属（`each (_ * 2) { }` 仍违规）；嵌套前缀结构内部的 `_` 属内层自有绑定，遮蔽外层、不受此限。

## 其他

- while 守卫每轮重评，守卫内 `@` 调用副作用被放大——守卫保持纯；
- repeat-N 糖（`each 5 { }`）搁置缘由见 [spec/10-废案](../spec/10-废案-REJECTED.md)；
- break/continue 为远期（plain break = 停止并以此前收集为数组值），见 [spec/11-路线图](../spec/11-路线图-ROADMAP.md)。
