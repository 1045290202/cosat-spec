# 循环设计决策

对应 [docs/07-循环](../docs/07-循环-LOOP.md)。

## 收集开关 = 体尾分号的动机

- 用户定向"循环能有返回值"，但不想引入 return/collect 关键字；
- 语义分号（`;` = 值丢弃）延伸到迭代维度即可零新增规则：体尾无分号 → 收集为数组（≈ map），带分号 → 不收集（≈ forEach，零收集开销）；
- 编译期由 Block.tail 判定，副作用循环不生成任何收集代码。

**空值也入列**：体块值一律收集，静默跳过空值属被否决的隐式魔法——筛选语义应显式走守卫形态或库函数 filter，而非靠收集器猜。

## 源层 `_` 白名单的三条理由

源表达式顶层禁止 `_` 作子表达式成分（`_ * 2`、`_ * _`、`f, _` 均编译错；唯一合法 = 站点位单独 `_`）：

1. **单字符陷阱**：`~ _ { }` 与 `~ _ * 2 { }` 一字之差语义大变；
2. **需求全部有更清晰等价形态**：站点分解 `data -> @double -> ~ _ { 体 }`、match 选源 `data -> ? _ { … } -> ~ _ { 体 }`、链上定义中转 `data -> def d; ~ d * 2 { 体 }`；
3. **从严到宽安全演进**：将来放开不破坏既有代码。

括号分组不改变 `_` 层级归属（`~ (_ * 2) { }` 仍违规）；嵌套前缀结构内部的 `_` 属内层自有绑定，遮蔽外层、不受此限。

## 其他

- 条件型守卫每轮重评，守卫内 `@` 调用副作用被放大——守卫保持纯；
- repeat-N 糖（`~ 5 { }`）搁置缘由见 [docs/10-废案](../docs/10-废案-REJECTED.md)；
- break/continue 为远期（plain break = 停止并以此前收集为数组值），见 [docs/11-路线图](../docs/11-路线图-ROADMAP.md)。
