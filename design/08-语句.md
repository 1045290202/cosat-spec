# 语句与分号设计决策

对应 [docs/08-语句](../docs/08-语句-STATEMENTS.md)。

## 语义分号的双重职责

`;` 的唯一语义 = **数据未到终点，值在此丢弃、流继续**（Rust 语义分号方案，2026-08 定案）。由此派生：

- **分隔职责**：块中 / 顶层语句间分号必需（表达式连排无法切分）；块尾后随 `}` 无分隔需求，分号只剩语义作用；
- **块值职责**：块尾无分号 = 值出口（块值流出）；带分号 = 值丢弃、块值为空值；
- **函数隐式返回**：返回值 = 体块值，无 return 概念，提前返回用 match 分支表达；
- **副作用出口根治**：`@fn1;` 的分号即声明"返回值继续流动、不在此出口"，静默返回问题由此消除。

被否决的备选（显式 return / nil / ignore 函数 / 警告模式）见 [docs/10-废案](../docs/10-废案-REJECTED.md)。

## 出口纪律

"副作用函数返回值流入下游"是高频静默 bug 源——链中间站点必须是值变换，副作用函数只放语句位或链尾。类型系统落地前的风格规则；落地后由多出口同型检查与 void 流入下游编译错接管。

## 类型系统期收益

- 返回类型标注：`\ x => x * 2 -> def double: number;`；
- 多出口同型检查；
- void / nil 流入下游编译错拦截。

nil 字面量为可选补充（比较 / 占位场景独立有用时再引入），非本问题必要解。
