# 函数设计决策

对应 [docs/05-函数](../docs/05-函数-FUNCTIONS.md)。

## 双箭头动机（`->` 流动 / `=>` 定义）

- **嵌套可读性**：lambda 嵌入管道时定义与流向视觉分离——`data -> @(\ x => x * 2) -> @(\ y => y + 1) -> @g` 中管道、定义、体一目了然；
- **符号单一含义（公理 3）**：同一符号不兼职。单箭头方案下 `->` 在"数据流向下游"与"形参映射到体"两个方向间摇摆，嵌套时无法区分函数边界。

判定边界：两箭头出现在不同语法位置（`\` 后形参到体 vs 链段数据到目的地），词法与文法层均无歧义。

## 三位置三种角色（`\` 后即形参、`=>` 后即体、链首即实参）

角色的确定性来自位置而非类型推断，IDE 可立即切换提示模式：`\` 是首字符，编辑器见首字符即知"定义模式"，可做形参名新绑定提示与 shadow 检查。

## 参数重排的设计建议

大多数场景参数不超过 2–3 个，`@\ a, b => b, a` 足以覆盖；超过 3 个参数应考虑合并为对象（待类型系统期支持），而非在调用侧做复杂重排——**参数过多是函数设计问题，不应由调用者承担复杂度**。

## 纯重排 β-内联的定位

| 场景 | 归约方式 | 开销 |
| --- | --- | --- |
| 分支体字面 lambda（含计算） | β-内联展开（体代码直接嵌入） | 零闭包零调用 |
| 纯重排 lambda | 参数顺序直接重排 | 零闭包零调用零临时变量 |
| 函数引用 | 动态分发 | 正常调用开销 |

纯重排内联是一般 β-内联的特化：更激进（连临时变量都不需要），因为体全为形参标识符时可把形参引用直接替换为上游参数位置，重排后传给下游。生成层流程：识别 `@\` 模式 → 检查体是否全为形参引用 → 替换并直传。
