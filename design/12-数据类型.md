# 数据类型与值模型设计决策

对应 [spec/09-数据类型](../spec/09-数据类型-TYPES.md)。2026-08-25 与用户逐轴讨论定案。

## 为什么单一 number（IEEE-754 双精度）

三候选：单一 double、int/float 分家、任意精度整数。选**单一 double**：

- v0.1 无类型系统，分家意味着跨型运算规则、提升表、两套字面量规则全部要在无静态检查的世界里靠运行时约定硬扛——文档面翻倍换不来编译期保障；
- 脚本语言先例充分（JS Number），±2^53 安全整数覆盖数组索引等实际场景；
- 代价明示：大整数不精确、`0.1 + 0.2` 类表示误差存在。需要精确大整数的场景等类型系统期拆分——届时新增 int 不改变既有代码语义，迁移非破坏。

## NaN != NaN：忠实 IEEE

备选是特设 `NaN == NaN → true`（数学直觉派）。拒绝理由：算术完全遵循 IEEE 是一条零记忆成本的规则；特设例外会制造「比较结果与硬件及主流语言不一致」的第二套心智；「严格相等」在 JS 同款行为下已有大量用户直觉。`-0 == 0 → true` 同理随 IEEE。

## 分隔符 `_` 与占位符的词法分流

`_` 表面上获得第三种出场（占位符 / 标识符成分 / 数字内分隔），实为无冲突：

- 公理 3 约束的是符号作为**语法角色**的兼职，不是字符参与 token 拼写——字母同时出现在标识符与注释里同理；
- 分流判定唯一且词法级：数字 token 必以数字开头，`_1000` 归标识符、`1_000` 归数字，首字符一锤定音，无上下文回溯；
- 弱形态全禁（尾随 `1000_`、连续 `1__000`）是公理 5「弱者非法防 typo 静默漂移」的直接实例。

用户定向：加分隔符，不加科学计数法与进制前缀（后者归远期，见 [11-路线图](../spec/11-路线图-ROADMAP.md)）。

## 未知转义为什么是编译错而不是透传

静默透传（`\q` ≡ `"q"`）的债务有现成先例：Python 对无效转义从静默放行逐步走到 DeprecationWarning 再到 SyntaxWarning——吞错债最终要还。Cosat 公理 5 已有同构先例（紧贴 `\x` 编译错、站点缺 `@` 可编译检查），转义集封闭让 typo 在编译期暴露。五项最小集覆盖最高频需求；`\u{...}` 码点转义随完整集归远期。

## 字符模型：码点而非 UTF-16 或字素簇

| 候选 | 判定 |
| --- | --- |
| UTF-16 编码单元 | emoji 拆代理对，索引语义反直觉，现代语言弃用方向 |
| 字素簇（Swift 式） | 用户感知最正确，但簇判定依赖 UAX#29 **版本化表格**——规范无法把结果写成封闭集，实现成本 v0.1 不堪重负 |
| Unicode 码点（Rust char 序列式） | 规范可封闭定义、遍历确定；代价：组合 emoji / 带音符字符拆成多码点 |

选码点并诚实标注代价；字素簇迭代可作远期库层能力，不进核心语义。

## 严格布尔：拒绝真值表

真值表方案三条否决理由：隐式转换表违反与「接收点显式」同族的显式性哲学；「空数组是否为假」取决于在途提案的可变性结论——表根本列不全；条件位静默吞错正是本次值模型要杜绝的 JS 老路。when/while 守卫「布尔表达式」是既有文字（[06](../spec/06-匹配-MATCH.md)、[07](../spec/07-循环-LOOP.md)），本决策把它升格为全语言条件语境统一约束并补运行时错误兜底。

## 「无空值」从事实升格为立场

废案已记录 nil 字面量降级为可选补充（返回值之争的副产物）。值模型把它升格为明文立场：值域六类**封闭列举**，无第九类。辨析一处长期易混点：块值为「空」（尾分号，[08-语句](../spec/08-语句-STATEMENTS.md) 出口纪律）是流控制语义，不是一种值。未来若引入 nil 走废案预留的可选补充流程，须先回答 match 穷尽性与点位模型的交互。

## `==` 为什么是总函数（跨类型 false 而非运行时错误）

若类型不同即运行时报错，`==` 变成偏函数：「防御性地比较两个可能异构的值」反而没法写——而 match 字面量分支正依赖这种比较；数据流推理中每一跳 `==` 都会成为潜在中断点。false 总函数保持 [02-符号](../spec/02-符号-SYMBOLS.md)「严格相等」的字面义：无强制的相等 = 类型不同即不等。它在 §9.8 登记表中作为唯一跨类型合法运算显式列出，是原则的明示例外而非暗设。

## 复合值引用同一性

用户定向（2026-08-25）：函数/数组/对象按引用比，内容级比较后续另议。先行定案的可行性论证：不可变重建路径（数组提案方案 A）下「同内容不同实例」判 false 是自觉代价；容器可变路径（方案 B）下同一性恰是自然语义——两条在途路径都不与本章冲突，故可以现在定案而不越权代定结构内部规则。函数按内容比较不可行：闭包捕获环境使「内容相等」无从定义。

## 运算符分派原则与 JS 的三条界线

讨论轨迹：先定向「运算符纯数值、拼接未来用其他符号」，随后提出重载机制设想，收敛为**原则 + 首个实例**。与 JS 的界线：

1. 分派只发生在同型组合，混合恒错误——JS `"a" + 1` 静默拼接的行为被显式消灭；
2. 无 toString 兜底；
3. 实例登记是封闭白名单制，不是任意类型的开放重载。

内部一致性：`==` 已经按类型分派（基础三类按值 vs 复合引用同一性），「运算符语义随操作数类型变化」在值模型内已有先例，公理 3 张力可控——`+` 的两个实例共享「二元组合」语法角色，文法形态零新增。与 [11-路线图](../spec/11-路线图-ROADMAP.md) 第 7 位前缀协议互补：那边管新符号的前缀注册（禁中缀不变），这边管既有中缀符号的类型实例扩展，互不侵越。

风险记录：`a + b` 行为依运行时类型而异，文档面增加；首个实例选 string 拼接因其高频且与主流直觉一致。
