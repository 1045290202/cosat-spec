# 匹配设计决策

对应 [docs/06-匹配](../docs/06-匹配-MATCH.md)。

## 关键词拆分动机（2026-08-22）

单一 `?` 前缀承载 cond / switch 双型的成本随规则细化持续上升：守卫分型表、"型内禁混"检查、`_` 角色随语境变义。拆分为 `match`（值分发）/ `when`（条件分发）后判型在 token 层完成，跨型规则整体消失。论证要点：

1. **与 2026-08-18「统一 `?` 符号」定向不矛盾**：当时否决的是 `if/elif/else` 的命令式形状；本次关键词保住 Cosat 形状（分支块 + `守卫 : 接收者`），只换头部 token；
2. **词 token 先例**：`def` 已确立链中线词 token 的合法地位；match / when 的使用频率层与 def 同层（低于 `@ \ _`）；
3. **符号预算**：`?` 回池（作为待定三元候选保留），缓解 [02-符号](../docs/02-符号-SYMBOLS.md) 的符号稀缺；
4. **主流先例**：Rust / OCaml 以 `match` 专职值分发、布尔条件分发独立成构造；Cosat 的 when / match 分工与之同构。

## lambda 仍不可替代的场景

分支体泛化（v0.8）后 lambda 不再是体的必需形态，但三种场景仍需它：

1. **闭包捕获**：内层引用外层变量；
2. **多语句体**：语义分号控制多条语句；
3. **显式命名参数**：`\ x =>` 的名字比 `_` 清晰。

## 分发形态与性能

- 字面 `\ …` = **静态分发**：生成器 β-内联（字面 lambda 恰好应用一次，直接展开，零闭包分配零调用）；
- 引用 / 泛化表达式 = 直接嵌入或动态分发：编译期不可内联；单赋值 `def` 可传播回字面；运行时单态由内联缓存兜底。

设计要点：**文法即分发选择权**——写哪种体形态就得到哪种分发策略，无需注解或提示器。守卫顺序映射条件链，`_` 对应最终分支；值位以隔离作用域包裹取值。

## 应用与选择正交

体写 `@pass`（调用）与 `pass`（裸引用）的区分由全局"引用 / 调用"规则接管，match 不引入第三种语义：分支值可以是函数本身，从而支持路由表、策略选择等高阶用法。
