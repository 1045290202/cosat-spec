## `>>` 退役与体边界统一

| 被取代形态 | 取代者 | 取代原因 |
| --- | --- | --- |
| `>>` 存储运算符（`值 >> def 名字`） | 链站点 `-> def 名字`（tee：绑定并透传） | `->` 收敛为唯一流向符号；存储收编进链模型，def 与 `@fn` 对称（内置绑定 / 内置调用）；少占一个符号（回未占用池）。顺带定案：链式绑定合法、重绑定判死为无变异遮蔽。全文见 [design/09](../design/09-链上定义.md) |
| 语句位单行体含管道（`\ x => x -> @double -> @inc;`） | 块体 `\ x => { x -> @double -> @inc }` | 体边界统一：存储改走 `->` 后，若语句位体仍可含管道则「定义函数」与「体内 tee 绑定」两解并存；一切位置单行体到第一个未配对 `->` 止，消灭位置特例与歧义 |

## 关键词拆分与优先级重排

| 被取代形态 | 取代者 | 取代原因 |
| --- | --- | --- |
| `?` 前缀统一判断家族（cond / switch 双型） | 关键词 `when`（条件分发）/ `match`（值分发） | 判型成本（守卫分型表、「型内禁混」检查、`_` 角色语境变义）随规则细化持续上升；拆分后判型在 token 层完成，跨型规则整体消失。与 2026-08-18「判断家族统一 `?`」定向不矛盾——当时否决的是 `if/elif/else` 的命令式形状，本次保住分支块形状只换头部 token；词 token 先例为 `def`；`?` 回池缓解符号稀缺并解封三元候选。全文见 [design/06](../design/06-匹配.md) |
| `~` 前缀四形态单符号（遍历 / 遍历带守卫 / 条件型 / 站点位） | 关键词 `each`（遍历 / 遍历带守卫 / 站点位）/ `while`（条件循环） | 条件型与带源形态结构差异最大（无源、守卫重评、不可入链、`_` 规则相反）；拆分后源扫描只属 each、守卫重评只属 while，各自成文不再互相引用解释。全文见 [design/07](../design/07-循环.md) |
| 「比较高于加减」反主流优先级 + 输出层按优先级补括号方案（原已知问题修复方向） | 主流层级 `* /` ＞ `+ -` ＞ `< >` ＞ `==`（用户定向：加法优先级高于比较） | 内部层级 = 常规解析层级后，AST 原样输出即可被正确复读，「优先级与输出不协同导致语义反转」根治；补括号方案作废。链式比较本被单可选文法禁写（`comparison` 只允许一次比较），重排零表达力损失 |
| 条件循环示例谓词 `@done?` | `@running` | 原写法非法（[01-词法](../spec/01-词法-LEXICAL.md) 标识符文法不含 `?`，运算符表无后缀 `?`），三处示例均无法通过词法；且极性误导——臂在守卫为真时执行、全假退出，名为 done 却继续轮转。「标识符尾缀 `?`」方案一并否决：公理 3 符号单一含义存在张力，且退役的 `?` 已保留给待定三元候选 |
