## §10 否决方案及原因（v0.7 及以前）

### 调用与函数形态

| 方案 | 否决原因 |
| --- | --- |
| 括号调用 `g(_, true)` | 与"目的地殿后"公理不同构；站内函数名前置 |
| 空格参数 `g _ true`（F# 式） | `g 1 + 2` 优先级陷阱；段式方案下无存在必要 |
| postfix 无分隔 `-> _ (a+b) g` | 函数名边界纯位置约定；调用点不可搜索；错位静默 |
| `->>` 构造符（任何位置） | 符号视觉拼接感；前缀形式强制块，单行函数过重 |
| `a, b -> { … }` lambda | 实参/形参文法不可区分（真歧义） |
| `:param` 冒号形参 | 与远期类型标注 `x: T` 视觉反向冲突 |
| 中段无 `_` 隐式填末坑 | 掩盖"返回值丢弃"错误，改为编译错（数据断流检查） |
| `-> f;` 零参调用 | 🚫 废弃提案：由 `@f` 接管（语义更纯） |

### 判断（match / 三元）

| 方案 | 否决原因 |
| --- | --- |
| `?` 守卫列表曾短暂归 match 专用后又被 if 关键字方案替代 | 最终回归：`?` 前缀=match 定案（2026-08-18），判断家族统一 `?` 符号 |
| `if / elif / else` 关键字 | 不够简洁、分支不直观；且二元/多路分离后无存在必要（二元待定见 [06-匹配 §7.2](./06-匹配-MATCH.md)） |
| `then` 行内糖（`if c then a else b`） | `? :` 表达式形态可覆盖；随 if 关键字方案一并搁置 |
| match 符号 `\|`（Haskell guard 风）/ `?\` | `?` 前缀统一判断家族后两者不再需要；`\|` 回闲置池 |
| `??` 作 match 符号 | 与 JS/PHP nullish coalescing 认知冲突；保留给远期空值合并 |
| `x < 0 ? { A; } : { B; }` 中缀块三元 | **待定**：块形态不够 Cosat 化（用户评价）；表达式形态是否保留一并待定 |
| switch 分支左侧裸标识符（`? x { y -> A }`） | 比较/绑定在无类型系统下真歧义，v1 编译错；`_` 守卫表达式放行，绑定留给远期显式语法 |
| match 支路去块（`守卫 -> 裸表达式`） | 双重不可行：靠 `;` 切分则与语义分号冲突（分号=丢弃→分支无值出口）；无 `;` 则与下一行守卫贪婪连接（`-> a` + `+1 > 0 -> b` 解析为 `a + 1 > 0`）——块是唯一双赢边界 |
| 匿名体方案 `守卫: x -> x + 1`（不带 `\` 的体形态） | 被"分支体 = 函数"提案取代：`\ x -> x + 1` 复用现有 lambda 字面量（零新文法），且体可为函数引用（路由/策略表）——匿名体两者皆无（v0.8 进一步泛化，见下节） |

### 返回值与 `_`

| 方案 | 否决原因 |
| --- | --- |
| 返回值方案：显式 return / nil 字面量（Ruby 模式）/ OCaml ignore / Swift 警告 | 采纳 **Rust 语义分号**（`;` = 数据未到终点，值继续流动；块尾无分号 = 出口）；nil 降级为可选补充；副作用出口静默返回问题（`@fn1;` 尾返回值意外流出）由此根治 |
| `_` 多处引用（`_, _` / match 内+顶层）曾短暂放行后收紧 | **最终定案：绑定模型 + 恰好一次引用**；多引用的隐式 mutation 风险（先求值成员修改值）+ 可由变量中转完全替代 + 从严到宽安全演进；Kotlin `it` / Clojure `%` 为多引用先例、Scala `_`（独立绑定）为反面教训，Cosat 取最保守形态 |
| switch 型 `_` 作用域 = 仅分支左侧（支路块内 `_` 无定义） | **修案（2026-08-19，v0.5）**：`_` 绑定贯穿整个 match 块——与公理 6"接收 ≠ 使用"一致、修补循环体内元素在支路块不可达的缺口、与 lambda 形参/合并段成员一致。代价：scrutinee 为变换表达式时支路块内 `_` 是变换后的值（Scala 式遮蔽代价） |
| v0.5 贯穿绑定（支路块内 `_` = 被匹配值） | **v0.7 废止**：体 = 接收者，数据经形参具名（`\ v -> …`）或零参弃用——显式形参取代隐式 `_`，体内部混淆（尤其体内有管道时 `_` 满天飞）根治；`_` 收敛为"位置型（落点）+ 守卫引用"两种出场 |

### 循环

| 方案 | 否决原因 |
| --- | --- |
| 循环语法：each/while 关键字、`for x in xs`、`while (c) {}`、`loop {}` | 收敛为 `~` 双型（2026-08-18 定案，[07-循环](./07-循环-LOOP.md)）：关键字方案被否决（用户定向符号前缀，入 `\` `?` 家族）；`for x in` 绑定名前置于数据违反"目的地殿后"；`while (c)` 括号调用既视感 + 条件循环本被重绑定未定案阻塞；`loop {}` 由 `~ { _ -> { … } }` 惯用形覆盖（随 break 解禁） |
| 循环无返回值 / 值位禁用方案 | 改为**体尾分号开关**（用户定向"循环能有返回值"）：体尾无分号 → 收集为数组（值出口），带分号 → 不收集——语义分号延伸到迭代维度，编译期判定零运行时代价 |
| 循环符号候选 `^`（备选）、`&` `%` 及竖线 | `~` 定案：波浪周期隐喻 + 前缀位无二元争夺——`&` `^` `%` 与竖线是未来逻辑/位/模二元运算的仅存候选（Cosat 尚无逻辑与/或）；`~` 的唯一索赔人是 JS 位非，互操作走函数，池已登记（[02-符号](./02-符号-SYMBOLS.md)） |
| repeat-N 糖（`~ 5 { }` = 遍历 0..4） | 搁置：字面量糖与数字变量形式不一致（编译期无法识别），类型系统期统一解禁"数字即范围"；v1 以防误写编译错引导 |
| 源侧早终止语法化（takeWhile / find / break） | 否决：源侧截断与聚合归库函数（循环 = 源 × 体 × 出口分工），`~` 只管"源 → 体 → 收集"；break/continue 为远期（plain break = 以此前收集为数组值） |
| 站点位完全禁 `~` | 放宽为**源必须 `_`**：`data -> ~ _ { 体 }` ✓——上游绑定源位，与合并段 `_` 模型同构；`data -> ~ xs { }` 仍禁（上游断流）；条件型不可入链 |
| 源内 `_` 作运算成分（`data -> ~ _ * 2 { }`，引用恰一次） | 从严禁止：**源层 `_` 白名单**（2026-08-18 补案）——源层 `_` 仅单独作源；`~ _ * _` 两处引用更在必禁之列。理由：单字符陷阱；需求全部有更清晰等价形态（站点分解、match 选源、变量中转）；嵌套结构自有的 `_` 不受限 |
| 循环体 = 块 + `_` 引用元素（v0.4 形态） | **v0.7 体接收者化**：体 = 接收者（`\ x -> …` 或函数引用），元素经形参具名；收集开关 = 体的值出口，语义分号零新增规则；v0.5 留名模式与遮蔽链随之作废（v0.8 进一步泛化，见下节） |

### 分支箭头与接收点

| 方案 | 否决原因 |
| --- | --- |
| 分支箭头分隔符 `守卫 -> { 块 }`（含 v0.6"四位置同义"诠释） | **v0.7 重构（2026-08-19，用户定向）**：分支改为 `分支左侧 : 接收者`——分支箭头实为分隔符而非数据流（守卫吃数据产出布尔、支路吃的却是数据本身，单箭头两头对不上）；ML 家族同用法但无管道 `->` 双重身份，属 Cosat 特有问题。`:` 启用（守卫扫描到 `:` 止），`->` 回归纯数据流 |
| 接收点规则散落各处（站点形态表 / `_` 恰好一次 / 源层白名单 / 断流检查 / 裸 `@` 与块禁令） | 抽象为**公理 6「接收点显式」**（2026-08-18，用户洞察）：`->` 的本质 = 暴露右侧接收者的接收点与实参对应——接收点必须显式、裸露、唯一、禁表达式；链外自带头部操作数不受限——上述散落规则统一为本公理的推论 |

## v0.8 取代记录（2026-08-19/20 定案）

以下为 v0.7 定案形态被 v0.8 提案取代的记录（对应定案规则现见 [04-链模型](./04-链模型-CHAIN.md)、[05-函数](./05-函数-FUNCTIONS.md)、[06-匹配](./06-匹配-MATCH.md)、[07-循环](./07-循环-LOOP.md) 对应章节）：

| 被取代形态（v0.7） | 取代者（v0.8） | 取代原因 |
| --- | --- | --- |
| 隐式调用 `data -> f`（站点裸标识符自动调用） | 显式调用 `data -> @f`；裸标识符站点编译错 | `@` 收敛为唯一调用标记：裸标识符 = 永远引用、`@` = 永远调用，传引用/传结果在文法层可区分（公理 3/5），并支撑点位数量校验模型 |
| `->` 兼任定义箭头（`\ x -> body`） | `=>` 专职定义（`\ x => body`），`->` 仅数据流 | 符号单一含义（公理 3）；嵌套管道中定义/流向视觉分离；与 JS/TS 箭头函数直觉对齐 |
| 分支 / 循环体必须是函数（裸字面量 / 算式作体编译错） | 体 = 接收点位匹配的任意表达式（字面量 0 位、`_` 表达式 1 位、`@fn` = 形参位） | 常量分支免包装（零 lambda 样板）；v0.7 约束是点位模型的特例（函数 = 有接收点位的表达式）；点位编译期可算，无需类型系统 |
| 循环三形态（遍历 / 条件 / 站点） | 新增**遍历带守卫** `~ 源 { 守卫 : 接收者 }` | 遍历 + 过滤的惯用形免 lambda/match 包装（2026-08-20 定案） |
| 无多返回值；参数重排靠中转变量 | 体逗号表达式 = 参数组返回；`@\ a, b => b, a` 惯用形 + 纯重排 β-归约 | 正交组合既有原语（`@` + `\` + 参数组）零新符号；纯重排零闭包零调用零临时变量 |
| v0.7 禁 `data -> @fn`（单字符陷阱） | v0.8 禁 `data -> fn`，`@` 为站点常态 | 陷阱消除方向反转：显式化使"缺 @"成为可编译检查的形态（防 typo 静默漂移的公理 5 新实例） |
