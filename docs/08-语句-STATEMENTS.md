## §8 语句与程序结构

| 结构 | 语法 |
| --- | --- |
| 程序 | 语句序列 |
| 块 | `{ 语句* }` |
| 块值 | 块尾**无分号**语句的值 |

**语义分号（🔒 定案）**：`;` 的含义 = **数据未到终点，需要继续流动，不能在此被拦住**（该值在此处被丢弃，流继续）。

- **双重职责二分**：块中/顶层语句间的分号必需（分隔职责：表达式连排无法切分）；块尾后随 `}` 无分隔需求，分号只剩语义作用；
- **块值规则**：块尾最后一条语句**无分号** → 其值为块值（流出 = 出口）；**带分号** → 值丢弃，块值为空值；
- **嵌套块统一**：任何位置的块语句，其块值同样受分号控制——`{ a; { b } }` 外层块值 = b；`{ { @fn1; } }` 内层分号丢值，外层流出空值；无特例；
- **函数返回值 = 体块值**（隐式返回）：`\ x => { x * 2 }` 值出口（无分号）；`\ x => { x -> @log; }` 副作用出口（分号丢弃返回值）；
- **副作用出口的静默返回问题由此根治**：`@fn1;` 的分号即声明"fn1 的返回值继续流动、不在此出口"；
- **迭代维度延伸**：循环体尾分号 = 收集开关（见 [07-循环 §7.3.1](./07-循环-LOOP.md)）；分支单行体间分号 = 值丢弃（见 [06-匹配](./06-匹配-MATCH.md)）；
- 词法注记：块尾值贴 `}` 的写法（`x + 1}`）比贴 `;` 更安全——词法器对 `}` 有显式边界处理，无贪婪吞并问题；
- 实现注记：AST 需记录块尾语句有无分号（如 `Block.tail` 字段）；
- **出口纪律（风格规则，类型系统前）**：一个函数的所有出口（match 各支路块值、函数体尾）应流出同类型值；值位 match 各支路应产出值或显式无值（空块）；副作用函数只放语句位或链尾，链中间站点必须是值变换——"副作用函数返回值流入下游"是高频静默 bug 源；
- **类型系统期收益**（远期）：返回类型标注（`\ x => x * 2 >> def double: number;`）+ 多出口同型检查 + void/nil 流入下游编译错拦截；
- **nil 字面量** ⏳：可选补充（比较/占位场景独立有用时再引入），非本问题必要解；
- 历史注记：返回值处理的诸备选方案（显式 return、nil 字面量、忽略函数、警告模式等）均已否决，最终采纳语义分号方案。完整否决记录见 [10-废案](./10-废案-REJECTED.md)。
