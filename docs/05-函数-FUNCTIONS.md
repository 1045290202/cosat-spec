## §6.1 定义（构造 + 存储）

**`\ 形参 => 体`**（定义箭头为 `=>`），体 = 表达式（单行）或块（多行）：

```cosat
\ x => x * 2;                          # 单行 lambda
\ x, y => x + y;                       # 多参
\ => 42;                               # 零参

\ x => {                               # 多行块体
    x * 2 >> def m;
    m + 1                              # 块尾无分号 = 出口：块值 = m + 1（隐式返回）
} >> def doubleIncr;

\ x => x * 2 >> def double;            # 定义 = 构造 + 存储
```

### 双箭头动机（🔒 定案）

`->` 与 `=>` 分工的动机：

- **嵌套可读性**：lambda 嵌入管道时定义与流向视觉分离，函数边界一目了然：

```cosat
data -> @(\ x => x * 2) -> @(\ y => y + 1) -> @g
#      管道   定义  体    管道   定义  体    管道
```

- **符号单一含义（公理 3）**：`->` 唯一含义 = 数据流（管道），`=>` 唯一含义 = 函数定义（形参 → 体），同一符号不兼职。

判定边界——两种箭头出现在不同语法位置，词法与文法层面均无歧义：

| 位置 | 用哪个 | 示例 |
| --- | --- | --- |
| `\` 后形参到体 | `=>` | `\ x => x * 2` |
| 链段数据到目的地 | `->` | `data -> @fn` |
| lambda 体内嵌套管道 | `->` | `\ x => x -> @fn`（`=>` 只在定义处出现一次） |

### 体边界规则（函数声明优先级最低，🔒 定案）

`>>` 与 `->` 的优先级均高于函数声明：单行体自 `=>` 后开始扫描，遇到第一个**未配对**的终止符为止，配对块 / 括号内的同名符号不截断（扫描跳过配对单位）：

| 体所在位置 | 终止符 | 示例 |
| --- | --- | --- |
| 语句位 / `>>` 右侧 | `>>` 或 `;` | `\ x => x * 2 >> def double` = `(\ x => x * 2) >> def double` |
| 裸链中站点位（`@\`） | `->` / `>>` / `;` | `data1, data2 -> @\ a, b => b, a -> @fn`：体 = `b, a` |
| 分支体位 | `;`（语句位单行体分隔）/ `}` | `? x { _ > 0 : \ v => v + 1; _ : 0; }` |
| 循环体位 | `}` | `~ xs { \ x => x * 2 }` |
| 括号内 | `)` | `data -> @(\ x => x -> @f)`：体内可含管道 |
| 参数组成员（链首组） | `,` 或 `->` ⏳ | `,` 与 `->` 的优先级待定（见 §6.6 开放问题 7）；括号形 `(\ x => x * 2), data -> @apply` 无歧义可用 |

语句位无 `>>` 时体可含管道：`\ x => x -> @double -> @inc;`（`=>` 只在定义处出现一次）。块体以配对 `}` 闭合，不受截断影响。

### 定义语义

- **实参 / 形参区分**：`\` 后即形参、`=>` 后即体、链首即实参——三个位置三种确定角色；
- **IDE 友好**：`\` 是首字符，编辑器立即切"定义模式"（形参提示新绑定名、shadow 检查）；
- **递归**：函数定义可提升，体内可引用自身及互相调用；
- **返回值 = 体块值（隐式）**：块尾无分号语句的值流出（见 [08-语句](./08-语句-STATEMENTS.md) 语义分号）；副作用出口写分号（`\ x => { x -> @log; }`，log 返回值被丢弃）；无 return 概念，提前返回用 match 分支表达；
- **分次传参** ⏳：用显式闭包——`\ b => { 1, b -> @add } >> def addB;`；自动部分应用待类型系统后解禁。

### 官方示例：斐波那契

综合展示构造/存储、switch 型 match（泛化体）、括号嵌链、单表达式体：

```cosat
\ n => ? n {
    0 : 0
    1 : 1
    _ : (n - 1 -> @fib) + (n - 2 -> @fib)
} >> def fib;

10 -> @fib -> @print;                # → 55
```

配套文法：`primary → "(" chain ")"`——**括号分组内嵌链作为表达式**（链求值为调用结果，如 `(n - 1 -> @fib)`）；多语句体必须块（与 match 支路强制块同一双理由），单表达式体可裸。

## §6.2 调用

| 场景 | 写法 | 语义 |
| --- | --- | --- |
| 单参 | `data -> @f` | `f(data)` |
| 多参 | `a, b -> @f` | `f(a, b)` |
| 零参 | `@f` | `f()` |
| 链中合并多参 | `data -> _, x -> @g` | `g(data, x)` |
| 上游被 `@fn` 直接消耗 | `data -> @f1, x -> @g` | `g(f1(data), x)` |
| 动态站点 | `data -> (@@fn)` | ❓ 见 [§6.4](#64-站点位与接收点规则) 注记 |
| 内联调用 | `data -> @(\ x => x * 2)` | lambda 就 data 立即应用 |
| 匿名函数传参 | `(\ x => x * 2), data -> @apply` | `apply(lambda, data)`；裸形 `\ x => x * 2, data -> @apply` 的切分取决于 `,` 与 `->` 的优先级，待定（⏳ 开放问题 7） |

## §6.3 `@` 调用符（唯一调用标记）

**`@` = 调用（call）**。裸标识符永远是引用（不调用），`@` 标记该标识符是一个调用点。

| 写法 | 语义 |
| --- | --- |
| `fn` | 函数引用，不调用 |
| `@fn` | 调用 fn |
| `data -> @fn` | fn 接收 data 并调用 → `fn(data)` |
| `data -> fn` | **编译错**（站点位缺少调用标记） |

### 文法与操作数限制

- 文法：`@` callee，callee = 标识符 / dot 链 / 另一个 `@` 表达式（右结合）/ lambda 字面量（`@\ => body`，`@` 紧贴 `\`）；
- 操作数限制：`@1`、`@"str"`、`@(a+b)`、`@!f` 均编译错（`'@' requires a function reference`）；
- `@x`（变量持函数值）合法——高阶函数刚需；x 运行时非函数则抛运行时错误（类型系统前的既有代价）；
- 优先级：前缀，与单目同级，高于一切二元：`@f + 1` = `f() + 1`；
- **语义角色**：裸标识符 = 引用，`@标识符` = 调用，在任何表达式位置一致（参数组内 `f` 传引用、`@f` 传调用结果）。

### 多层 `@`：右结合，内层先执行，点位不跨层

`@@fn = @(@fn)`。**内层 @（离 fn 最近的）先执行**；点位（形参位）始终来自 fn 本身的定义，`@` 层数只是叠加零参调用的执行细节，编译器查 fn 定义即可，无需类型推断：

```
@@fn = @(@fn)

  内层 @fn：fn 暴露 1 个点位，接收 data → 执行 fn(data)
  外层 @  ：对 fn(data) 的返回值执行零参调用 → fn(data)()
```

| 写法（fn 为 1 参） | 展开（有左侧 data） | 展开（零参场景） |
| --- | --- | --- |
| `@fn` | `fn(data)` | `fn()` |
| `@@fn` | `fn(data)()` | `fn()()` |
| `@@@fn` | `fn(data)()()` | `fn()()()` |

### 立即调用家族（全部为既有原语的正交组合，零专用语法）

| 场景 | 写法 | 语义 |
| --- | --- | --- |
| 零参立即调用 | `@\ => 1;` | 立即执行，结果 = 1 |
| 零参块体立即调用（作用域隔离） | `@\ => { … };` | 立即执行，块内 `def` 不泄漏 |
| 数据流入 lambda | `data -> @(\ x => x * 2);` | lambda 就 data 立即应用（动态站点） |
| 多参流入 lambda | `1, 2 -> @(\ x, y => x + y);` | 参数组 + 动态站点 |
| 裸 `@\` 带参重排形（链中） | `a, b -> @\ x, y => y, x -> @fn;` | 体到 `->` 止（§6.1 体边界），见 §6.5 |
| 命名函数取值 | `@f;` | `f()` |

## §6.4 站点位与接收点规则

站点位（`->` 右侧）= **接收者**：必须自带显式接收点（公理 6），且 `->` 左侧参数数量必须与右侧点位总数匹配（[04-链模型 §5.1](./04-链模型-CHAIN.md)）。只允许：

| 形态 | 写法 | 接收点 | 语义 |
| --- | --- | --- | --- |
| `@` 标识符 / dot 链 | `-> @f`、`-> @obj.method` | f 的形参表（定义处声明） | 静态站点，显式调用 |
| `(` `@@` 表达式 `)` | `-> (@@fn)` | 返回函数的形参表 | 动态站点，显式括号表态 |
| `@(` lambda `)` | `-> @(\ x => x * 2)` | 内联形参 `x` | 内联函数站点（立即调用） |
| `? _ { 分支 }` | `data -> ? _ { … }` | 裸 `_`（arg 位） | match 段：上游 = 被匹配值 |
| `~ _ { 接收者 }` | `data -> ~ _ { \ x => x * 2 }` | 裸 `_`（源位） | 循环站点：上游 = 源，元素流入体接收者 |

**禁止**：

- 站点位裸标识符（`data -> fn`，缺 `@`）——显式调用为常态、隐式为非法，"缺 @"成为可编译检查的形态（公理 5）；
- 站点位裸 `@`（`data -> @`）；
- 站点位块（`-> {…}`，lambda/执行体不可区分）。

站点位循环**必须以 `_` 为源**（`data -> ~ _ { … }` ✓；`data -> ~ xs { }` 上游断流编译错），且源位仅限**单独 `_`**（`data -> ~ _, x -> @f` 编译错，参数组不可作源）；条件型循环不可入链（守卫不消费流数据）——详见 [07-循环 §7.3.4](./07-循环-LOOP.md)。类型系统落地后，若编译期可证明 `@fn` 返回函数类型，动态站点括号形态可进一步简化 ⏳。

> ❓ **动态站点语义待对齐**：`data -> (@@fn)` 存在 `fn()(data)` / `fn(data)()` 两解——按多层 `@` 右结合规则（内层先执行），两种展开对应不同的点位分配时机，需定案其一。

## §6.5 多返回值与参数重排

### 多返回值

函数天然支持多返回值——lambda 体为逗号表达式时，返回参数组：

```cosat
\ a, b => b, a              # 接收 2 个值，返回 2 个值（交换顺序）
\ a, b, c => a, c           # 接收 3 个值，返回 2 个值（丢弃 b）
\ x => x, x * 2             # 接收 1 个值，返回 2 个值（复制 + 计算）
```

多返回值函数的结果是一个参数组，可直接流入下游：`@\ a, b => b, a -> @fn` → `fn(data2, data1)`；下游形参数量与返回值数量不匹配则编译错（点位校验）。点位模型不变：多返回值函数作为**接收者**仍按**形参数量**暴露点位（[04-链模型 §5.1](./04-链模型-CHAIN.md)，点位由进入方向的数据消耗决定）；其结果作为参数组流向下一跳时，按**返回值数量**与下游接收点位校验（形参数量由定义确定，返回值数量由体确定——编译期可分析逗号表达式）。

### 参数重排惯用模式

形参顺序由定义者决定、上游顺序由调用者决定，不一致时用 `@\` 即时函数做参数变换，**不需要新符号**：

```cosat
# 交换两个参数
data1, data2 -> @\ a, b => b, a -> @fn               # → fn(data2, data1)

# 旋转三个参数
data1, data2, data3 -> @\ a, b, c => b, c, a -> @fn  # → fn(data2, data3, data1)

# 丢弃多余的
data1, data2, data3 -> @\ a, b, _ => a, b -> @fn     # → fn(data1, data2)

# 复制
data1 -> @\ a => a, a -> @fn                          # → fn(data1, data1)

# 重排 + 计算
data1, data2 -> @\ a, b => b, a + b -> @fn            # → fn(data2, data1 + data2)

# 组合：重排 → 调用 → 重排 → 调用
data1, data2
    -> @\ a, b => b, a -> @fn1
    -> @\ x => x, x * 2 -> @fn2
```

**设计建议**：大多数场景参数不超过 2–3 个，`@\ a, b => b, a` 足以覆盖。超过 3 个参数时应考虑合并为对象（待类型系统期支持），而非在调用侧做复杂重排——**参数过多是函数设计问题，不应由调用者承担复杂度**。

### 纯重排 β-内联优化

当 `@\` 即时 lambda 同时满足 **① 字面量**（非函数引用）、**② 纯引用**（体中每个表达式都是形参标识符的重排，无 `@fn`、无运算、无字面量）、**③ 单次应用** 时，编译器将其**内联为参数重排**，不生成函数调用：

```cosat
data1, data2 -> @\ a, b => b, a -> @fn
# 语义：fn(data2, data1)    ← 直接重排，零闭包零调用零临时变量

data1, data2, data3 -> @\ a, b, _ => a, b -> @fn
# 语义：fn(data1, data2)    ← 直接丢弃第三个参数

data1, data2 -> @\ a, b => b, a + 1 -> @fn
# ✕ 体中有计算 → 正常函数调用（先求值参数组再调用）

data1, data2 -> @\ a, b => b, (a -> @process) -> @fn
# ✕ 体中有函数调用 → 正常函数调用（先求值参数组再调用）
```

本优化是分支体字面 lambda β-内联（[06-匹配](./06-匹配-MATCH.md)）的**特化**——比一般 β-内联更激进：连临时变量都不需要，只在调用侧改变参数顺序：

| 场景 | 归约方式 | 开销 |
| --- | --- | --- |
| 分支体字面 lambda（含计算） | β-内联展开（体代码直接嵌入） | 零闭包零调用 |
| **纯重排 lambda** | **参数顺序直接重排** | **零闭包零调用零临时变量** |
| 函数引用 | 动态分发 | 正常调用开销 |

生成层归约流程：识别 `@\` 模式 → 检查体是否全为形参引用 → 是则将形参引用替换为对应上游参数位置 → 重排后参数直接传给下游。

## §6.6 开放问题

1. ❓ **参数组中裸标识符的点位**：`data -> @fn1, x -> @g` 中 `x` 暴露 0 位——方案 A：x 是已定义变量，取值入组（→ `g(fn1(data), x)`）；方案 B：裸标识符在参数组中非法。**倾向 A**；
2. ❓ **`@a.b` 的语义**：`@` 绑紧整个 dot 链（`@obj.method` = `(obj.method)()`，保持方法接收者语义）还是只对紧邻标识符调用（`obj().method`）。**倾向绑紧 dot 链**（一元运算符作用于完整操作数）；
3. ❓ **lambda 字面量体是否需要 `@`**：match / 循环体位的 `\ x => …`——方案 A：体位自动立即调用（不需要 `@`）；方案 B：也需要 `@`；方案 C：`\` 自带调用语义。**倾向 A**；
4. ❓ **零点位 fallback**：`data -> @@fn` 而 fn 为零参时右侧 0 位 ≠ 左侧 1 值——方案 A：编译错；方案 B：`->` 兜底投递。**倾向待定**；
5. ❓ **match / 循环体中函数引用的 `@`**：体中函数引用需要 `@`（与全局规则一致），lambda 字面量在体位自动调用（同问题 3 方案 A）。**方向已定，待落文**；
6. ❓ **内置 / 外部函数 arity 声明**：点位校验依赖编译期已知形参数量，`@print` 等内置 / 外部函数无 Cosat 定义可查——需要 arity 声明机制或末段放宽规则，待设计；
7. ⏳ **参数组内裸 lambda 的 `,` 切分**：`\ x => x * 2, data -> @apply` 存在两种自洽切分——组成员（apply 收到 lambda 与 data）vs 多返回值体 `x * 2, data` 流入 `@apply`。实质是 **`,` 与 `->` 的优先级问题，待定**；定案前括号形 `(\ x => x * 2), data -> @apply` 无歧义可用。
