## 结构性前缀与函数声明优先级

- **结构性前缀不入优先级表**：`\` `?` `~`（及定义箭头 `=>`）是结构开启符而非表达式运算符，不参与优先级比较，其作用域由**扫描边界规则**界定（见下）；
- **函数声明优先级最低**（🔒 定案）：`>>` 与 `->` 的优先级均高于函数声明。单行 lambda 体自 `=>` 后开始扫描，遇到第一个**未配对**的 `>>`（语句位 / 存储）、`->`（裸 `@\` 链中站点位）或 `;` 终止；配对块 / 括号内的同名符号不截断（扫描跳过配对单位）。因此：

```cosat
\ x => x * 2 >> def double;              # 解析为 (\ x => x * 2) >> def double：体到 >> 止
data1, data2 -> @\ a, b => b, a -> @fn;  # 体到 -> 止：体 = b, a，其后是新的链段
\ x => x -> @double -> @inc;             # 语句位无 >>：体内可含管道，体到 ; 止
```

- 块体以配对的 `}` 闭合，不受上述截断影响；分支体位扫描到 `;`（语句位单行体分隔）/ `}`，循环体位扫描到 `}`，守卫扫描到 `:`（见 [06-匹配](./06-匹配-MATCH.md)）——详见 [05-函数 §6.1](./05-函数-FUNCTIONS.md)。

## 已知问题

**优先级与输出不协同导致语义反转** ⏳：`1 < 2 + 3` 的 AST 为 `(1 < 2) + 3`，若按原样输出会被按常规优先级解析为 `1 < (2 + 3)`。修复方向：输出层按优先级补括号（见 [11-路线图](./11-路线图-ROADMAP.md)）。
