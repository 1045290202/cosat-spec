| 元素 | 语法 |
| --- | --- |
| 单行注释 | `# ...` |
| 多行注释 | `#$ ... $#` |
| 语句结束 | `;` |

### `=>` token

函数定义箭头 `=>` 为双字符运算符，加入词法器运算符识别表：

| 项 | 内容 |
| --- | --- |
| Token 类型 | `Arrow` 或 `FatArrow` |
| 匹配规则 | `=` 后紧跟 `>` → `=>`（贪婪匹配） |
| 与 `=` 的关系 | Cosat 无赋值运算符 `=`（存储用 `>>`），不冲突；`=` 被 `=>` 前导消费，无独立 `=` |
| 与 `>` 的关系 | `=` + `>` 合并为 `=>`，不会误判为 `=` 和 `>` |
| 与 `>=` 的关系 | 首字符不同（`>` vs `=`），贪婪匹配各走各路，无冲突 |

## 前缀空格规则（🔒 定案）

结构开启符 `\`、`?` 与 `~` 之后**必须跟空格**（`\ arg => …`、`? arg { … }`、`~ src { … }`，紧贴形式 `\x` / `?x` / `~x` 编译错）。

**例外**：`@` 保持紧贴——`@f`、`@\ arg => …`（`@\` 是调用 + 构造的复合前缀，`@` 紧贴 `\`，`\` 后仍须空格）。

理由：① 角色前缀与操作数视觉分离（紧贴易读作转义序列或组合 token）；② 永久隔离与字符串转义（`\n`）及未来符号组合（`?.` `??` `~=`）的词法/视觉冲突。

**实现注记**：空格规则的落地以 Token 记录空白或 span 为前置（见 [07-循环 §7.3.7](./07-循环-LOOP.md) 与 [11-路线图](./11-路线图-ROADMAP.md)）。

## 词法已知问题

- **贪婪吞并无回退** ⏳：运算符与 `;` 相邻会合并报错（`->;` → `Unknown symbol '->;'`），运算符后必须写空格。改进方向：最长匹配 + 回退；
- **字符串无转义** ⏳（实现时 `\n` `\"` 等在字符串扫描内部消化，不与代码层 `\` 冲突）；
- **错误信息无行列号** ⏳（Token 增加 span）。
