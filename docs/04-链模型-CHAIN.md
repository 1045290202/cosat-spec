## 文法（EBNF）

```ebnf
chain       = [ value ] , { segment } ;
value       = operand | param-group ;
param-group = operand , { "," , operand } ;
segment     = "->" , station
            | "->" , recv-group , "->" , station ;      (* 合并段 *)
recv-group  = recv-item , { "," , recv-item } ;
recv-item   = at-expr | def-binding | "_"
            | operand ;                                 (* 点位计数：@fn=N、def=1、裸_=1、其余=0 *)
station     = at-expr                                   (* 含 @(\ …) 内联 lambda *)
            | "(" , "@@" , operand , ")"                (* 动态站点 *)
            | def-binding                               (* 定义站点：绑定并透传 *)
            | "?" , "_" , branch-block                  (* match 段 *)
            | "~" , "_" , block ;                       (* 循环站点段，源仅限单独 _ *)
def-binding = "def" , identifier ;                      (* 恰好 1 个接收点 *)
```

## §5 链 = 值 段*

核心文法，统一零参 / 单参管道 / 多参调用三种形态：

- **值**：空（零参链首）、表达式、或逗号分隔的参数组；
- **段**（两种）：**直传段** `-> @f`（上游整体流向函数并调用，站点必须带 `@`）；**合并段** `-> 参数组 -> @f`（上游按点位填入参数组，与成员合并后流向函数）。

```cosat
data -> @f;                       # → f(data)              值=data，直传
a, b -> @f;                       # → f(a, b)              值=参数组，直传即多参
data -> @f -> _, x -> @g;         # → g(f(data), x)        直传 + 合并
data -> @h, _ -> @g;              # → g(h(), data)         合并段成员可为 @ 表达式
data, fn -> @g;                   # → g(data, fn)          裸标识符 = 传引用
data, @fn -> @g;                  # → g(data, fn())        @ = 调用，结果入组
```

## §5.1 点位分配模型

遇到 `->` 时编译器对每一跳执行三步：

1. **扫描右侧，收集接收点位**：

| 表达式类型 | 暴露点位数 |
| --- | --- |
| `@fn` / `@@fn` / `@@@fn` … | fn 的形参数量（点位不跨层） |
| `_` | 1（原样直通位） |
| 裸标识符 `fn`（无 `@`） | 0（引用，不消耗参数；❓ 待定案，倾向方案 A——见 [05-函数 §6.6 开放问题 1](./05-函数-FUNCTIONS.md)） |
| 数字 / 字符串字面量 | 0（值，不消耗参数） |

   嵌套 `? _ { … }` / `~ _ { … }` 暴露 1 位（arg 位 / 源位），嵌套 cond 型 / 定源循环暴露 0 位——完整计数表见 [06-匹配](./06-匹配-MATCH.md)。

2. **校验点位总数 = 左侧参数数量**，不等则编译错；
3. **从左到右逐表达式处理**：`@fn` 按形参顺序取走参数并求值、结果原位替换；`_` 取 1 个参数原样保留；0 位表达式直接求值。全部求值后组成参数组流入下一段。

```cosat
data1, data2, data3 -> @fn1, _ -> @fn2;
# 假设 fn1 取 1 参：第一跳右侧点位 2 ≠ 左侧 3 → 编译错（校验按跳进行，不跨 -> 累加）

data1, data2 -> @fn1, _ -> @fn2;      # fn1 取 1 参、fn2 取 2 参
# 第一跳（合并段）：@fn1 消耗 data1 → r1；_ 保留 data2 → 组 [r1, data2]
# 第二跳：[r1, data2] -> @fn2 → fn2(fn1(data1), data2)
```

多 `@fn` 同组各自消耗后结果组成参数组流向下游（`data1, data2, data3, data4 -> @fn1, _, @fn2, @fn3;`，各取 1 参 → `[fn1(data1), data2, fn2(data3), fn3(data4)]`）；独立链段则上一段结果流向下一段（`data1 -> @fn1 -> @fn2` → `fn2(fn1(data1))`）。

> ❓ `data -> @fn1, data2 -> @fn2` 按本节点位模型推导为 `fn2(fn1(data), data2)`（首段为合并段）。工作结论，待最终定案确认（见 [design/04](../design/04-链与下划线.md)）。

## `->` 统一语义

`->` 全语言唯一含义 = **把左边的东西送到右边的目的地**（公理 2 的箭头实例），且仅用于链段一处。

**段的本质 = 上游 × 接收者**（公理 6）：数据在右侧的可见形式 = f 的形参表 / 裸 `_`（arg 位 / 源位）/ 泛化表达式接收点位。

## 段判定规则

lookahead 到下一个 `->` 或 `;`，封闭无歧义：

| 区间内容 | 判定 |
| --- | --- |
| 含逗号或 `_` | 合并段（参数组） |
| `@标识符` / `@@标识符` | 直传段（显式调用） |
| `def 标识符` | 定义站点段（绑定并透传） |
| 裸标识符 / dot 链 | **编译错**（缺少 `@`） |
| 裸 `@`（无标识符） | 编译错（站点位禁裸 `@`） |
| `~` 且源为 `_` | 循环站点段（见 [07-循环 §7.3.4](./07-循环-LOOP.md)）；段扫描跳过配对块 |
| `? _ { … }` | match 段（上游 = 被匹配值，见 [06-匹配](./06-匹配-MATCH.md)） |

## `_` 绑定模型

`_` 的角色 = "**原样直通点位**"（上游数据也可直接被 `@fn` 形参位消耗）：

- 合并段内参数组成员（含成员表达式内部，如 match arg 位 `_`）中的 `_` 为同一绑定的引用；
- **`_` 恰好被引用一次**：顶层成员位或成员表达式内合计一处；零处 = 不需要 `_`，多处 = 编译错（`_, _` / `? _ {…}, _` 均非法）；
- **多视图需求用链上定义中转**：`data -> def d -> ? _ {…}, d -> @fn;`；
- **求值顺序**：参数组成员严格从左到右求值；`_` 绑定本身不可变；
- **内层遮蔽**：内层 match 的 `_` 绑定（arg 位 + 守卫位）遮蔽外层参数组的 `_`。

禁多引用的理由与语言先例见 [design/04](../design/04-链与下划线.md)。

## def 定义站点

`def 名字` 是内置**绑定**功能的接收者（与 `@fn` 内置调用对称），tee 语义——绑定后原值透传给后续段：

```cosat
data -> def d -> @next;               # d 绑定 data，data 继续流入 @next
a, b -> def p1, def p2;               # 各取 1 个：p1 = a, p2 = b
a, b -> def pair;                     # ✕ 编译错：2 值 ≠ 1 点位（多返回值只能解构命名）
data -> (_ + 1);                      # ✕ 泛化表达式 0 接收点，断流编译错
```

- **作用域**：def 一律绑定在**所在作用域**（程序 / 块 / lambda 体）；可见性从绑定点起——链前段与先前代码不可见，后续段与链后代码可见。不做链尾 / 链中的位置区分；
- **无变异**：`i + 1 -> def i` 是新的局部变量（遮蔽外层同名），不是重绑定；语言无赋值语义。条件循环的状态机形态因此改走递归或远期显式可变容器（[design/09](../design/09-链上定义.md)）；
- 链式绑定合法：`1 -> def x -> def y;`。

定案全文见 [design/09](../design/09-链上定义.md)。

## match 与链的结合

- **match 段**：`data -> ? _ { 分支 }`——上游数据为被匹配值，命中支路值为段输出，可继续流：`data -> ? _ { … } -> @next;`；
- **match 作为参数组成员**：`data -> ? _ { … }, x -> @fn;`——match 表达式（`_` 引用计一次）与 x 合并 → `fn(match(data), x)`；
- **切分判定**（块 `}` 之后的 token）：`;` → match 段结束；`->` → 输出流入后续段（含链尾 def）；`,` → match 是参数组首成员，参数组继续，后须 `-> @函数` 收尾；
- cond 型不可入链（守卫不消费流数据），限语句位 / 值位。

## 禁止的写法 🚫

| 写法 | 判定 | 原因 |
| --- | --- | --- |
| `data -> fn` | ✕ | 站点位缺少 `@`（显式调用） |
| `data1 -> @f1 -> data2, data3 -> @f2;` | ✕ | 第二跳点位不匹配（0 位 ≠ 1 值），数据断流 |
| `data1 -> @f1, data2, data3 -> @f2;` | ⏳ 待复核 | 解析确定（合并段），禁写是否解除待实现确认 |
| `a, b -> { … }` | ✕ | 站点位禁块；实参/形参文法不可区分（已否决的 lambda 形态） |
| `data -> _, _ -> @fn;` | ✕ | `_` 多处引用；同值双传用中转：`data -> def d; d, d -> @fn;` |
| `data -> ? _ {…}, _ -> @fn;` | ✕ | `_` 两处引用（match 内 + 顶层）；用 `data -> def d -> ? _ {…}, d -> @fn;` |
